## 0.2.0 搜索与参数窗口

用户要求在现有插件内增加按名称搜索、参数独立窗口，每行显示名称和类型。继续使用此前已确认的原生风格，模式仍为 Extension；视觉变化 2、动效 1、密度 8、素材依赖 1、宿主一致性 10。4px 间距与圆角、宿主颜色和字体、无装饰动效。源码、变量、调用栈和输出的位置保持原样。

配置栏中的名称输入框在数据库目录查询中过滤，忽略大小写、按名称包含匹配；返回最多 500 条并明确提示截断，进一步输入可查找原始前 500 条以外的对象。原生下拉列表保留模式、名称、参数签名与过程／函数标记，OID 区分重载。唯一结果自动选中并加载源码及参数。延迟响应不得覆盖较新的搜索结果。

参数窗口使用原生 dialog，按参数顺序显示名称、真实类型、文本输入和 NULL 选择。文本原样绑定，不要求 SQL 引号；空字符串与 NULL 分开。参数草稿仅保存在当前工作台内存，按连接和对象 OID 区分，不写本地存储。未命名参数显示 $1、$2。填写参数后可保存，点击开始调试也会先打开参数窗口确认。无参数对象显示明确空状态；不支持的参数模式显示原因。

最高风险是参数顺序、NULL 与字符串语义变化，使用数据库目录元数据，不按逗号拆分签名；保留后台逐参数 PreparedStatement 绑定和目标端类型转换。已授权的独立探针作为实库回归对象。

## 0.3.0 参数方向与返回值

沿用已确认的 Extension 设计，参数窗口新增方向列，序号、名称、类型、输入和 NULL 选择继续使用原有样式。纯 OUT 的值固定为空值，禁用其输入和 NULL 复选框，焦点跳过 OUT 到第一个可编辑参数。INOUT 允许初值或 NULL，和 IN 使用相同录入方式。

完成后复用右侧“变量与参数”显示名称、方向、类型和返回值。返回值按声明位置排列，标量函数的 RETURN 单独为第一行；NULL 显示为 NULL，大整数以文本显示。再次开始清除上次返回值；取消、异常不显示成功返回值。初值草稿和返回值分别保留，避免反复调试时初值被自动改变。

从 proallargtypes／proargmodes／proargnames 按声明位置读取元数据；全为 IN 时可回退 proargtypes。含输出时使用 JDBC CallableStatement，纯 OUT 只注册输出，INOUT 绑定输入并注册输出。过程采用 {call …}，带独立返回值的函数采用 {? = call …}，参数位置相应偏移。


## 0.4.0 OUT 游标结果

延续已确认的 DBX Extension 布局，底部输出区增加“输出／结果集”标签和游标选择器；不改变源码、变量和调用栈的位置。结果表头显示原始列名和类型，行号、NULL、空结果和截断状态均有明确文本。按列位置读取，保留重复列名及大小写，所有单元格通过 textContent 渲染。游标参数按用户实际使用范围仅开放 OUT，固定 NULL，无需录入。

后端沿 sys_type.typbasetype 解析底层为 refcursor 的域类型，最多 16 层并检查循环，不依赖类型名称猜测。使用 Types.REF_CURSOR 注册输出，在执行连接同一事务里读取、关闭全部游标后提交；异常回滚，停止中止连接。仅输出摘要随状态推送，表格数据通过 debug/result 按 generation 和 resultId 获取，避免状态轮询重复传输。前端校验连接、generation 和请求序号，过期数据不得覆盖新结果。


## 0.5.0 NULL 默认值与文本导入

模式为 Extension。沿用用户已确认的 DBX 原生风格：宿主面板／文字／主色变量、系统与等宽字体、4px 间距和圆角、无阴影；布局变化 2、动效 1、信息密度 8、素材依赖 1、宿主一致性 10。新增配置栏按钮和与参数窗口一致的 dialog，源码／变量／调用栈／结果区位置保持原样。最高风险是字符串、NULL 和实参顺序语义，使用本地词法分析与数据库参数元数据核对。

首次打开所有参数默认 NULL；IN／INOUT 输入框保持可编辑，input 事件在有内容时取消 NULL，清空时恢复 NULL；手动勾选 NULL 清空原值，手动取消可保留空字符串。OUT 输入和复选框始终禁用。保存草稿仍按连接和 OID 隔离。

“粘贴调用文本…”对话框复用原生边框、标题、错误状态与底部按钮；主区为可滚动等宽文本，解析成功进入既有参数窗口。词法分析分离字符串／注释／名称／数字与标点，按括号层级分割，保留大整数原文与空字符串。只提取一次目标调用的字面值或变量值，未声明／复杂表达式／控制流等明确拒绝。数据库签名确定 OUT 自动 NULL 和名称映射。重载存在歧义时留在导入窗口要求选择签名与 OID；不会按推测类型选择。

解析仅调用目录、参数与源码读取 API，不执行用户粘贴的匿名块。参数窗口明确标示导入数量、OUT 初值归空、打印语句处理；保存与开始调试保持既有分步交互。文本编辑、关闭窗口、连接变化使在途导入失效，失败保留先前有效对象和草稿。


## 0.5.1 导入空值归 NULL

按用户反馈，粘贴调用文本中的空字符串（含普通、N、q 引用）统一归为 NULL。声明初值、调用前赋值、直接及命名实参、变量传递共用字面值解析规则；数字 0、布尔值和含空格的非空字符串原样保留。参数窗口的空行在导入、保存、重新打开时都勾选 NULL，最终执行参数数组传 null。手动输入后的既有 NULL 切换交互保持一致。

## 0.8.0 可选记住密码

延续用户已确认的连接窗口与原生视觉风格，在密码行下加入“记住密码（macOS 钥匙串）”及保存状态。新连接默认不勾选；已有密码则勾选并显示“已保存，留空使用；输入可更换”。密码不回填 UI。保存配置可明确存储／删除密码；保存并连接只在连接验证成功后更新钥匙串。测试按钮只使用密码，不修改已保存项。取消勾选并保存可删除；删除连接同步删除该项；普通断开／关闭不删除已记住的密码。

宿主未给插件内部配置提供独立凭据 API，因此使用固定服务名的 macOS Security helper，通过匿名进程管道接收操作和新密码，返回密码仅交给 Java 后端，前端只接收有无密码。原连接 JSON 仍只保留八个非密码字段。钥匙串项按私有 UUID 和主机、端口、库名、用户名摘要绑定；改目的地不能复用旧凭据，保存目的地变更会移除旧项。重命名不影响密码。helper 不接收命令行密码、不使用 shell，不写临时密码文件或日志，不开放任意 service／account 枚举。

数据保存在本机登录钥匙串，不同步到 iCloud，不改变钥匙串访问控制。OS 要求本机授权时由用户完成。访问失败显示明确错误，可取消记住并手工连接；连接列表仍可查看。用合成凭据覆盖安全存储、重启、精确身份隔离、更换／删除、访问失败及失败连接不得覆盖旧密码。


## 0.9.0 Windows x64

Go launcher 拆分公共 Java 版本检查与平台进程实现。Windows 以不继承给子进程的 handle 持有私有 Job Object，在创建 Java 之前将自己加入 job，设置 JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE。子进程继承 job membership；宿主强制终止 launcher 时，最后一个 job handle 关闭，Java 和其 helper 一起终止。Java 子进程直接使用 launcher 的 stdin／stdout／stderr，正常退出码向宿主传递。macOS 保持 syscall.Exec。

Windows 固定服务前缀 helper 采用 Go 标准库 syscall 调用 Windows Credential Manager。CREDENTIALW 结构的 x64 ABI 通过运行测试确认；目标名仅接受本插件私有 UUID 加端点摘要，通用凭据持久化级别为 CRED_PERSIST_LOCAL_MACHINE（当前用户、本机），不枚举凭据。值使用与 Mac 相同的版本前缀，空密码同样能替换旧值；Windows 存储上限在 Java 和 helper 两处检查。界面只取状态及固定平台标签，读取密码仅在后端进行。

构建脚本在 Windows 本地临时 staging 编译 Java 和 Windows helper，再使用官方 x64 CLI 打包 launcher。打包成功后才复制 .dbxp 与 artifact.json 到目标目录；临时 staging 在 finally 清理，避免跨平台二进制混装及共享目录清理失败。专有 JDBC 与 Java 运行时不分发。

参考：Microsoft Learn 的 CREDENTIALW／CredWriteW、Job Objects／Nested Jobs 文档，以及 DBX 官方 CLI 的单平台 native packaging 实现。测试限制见 VALIDATION.md。

## 0.9.2 沙箱按钮与输入确认

DBX 官方插件文档指定 iframe 为 sandbox="allow-scripts"，无 allow-forms。在真实 Chromium 中，旧包的 submit 按钮被沙箱拦截，连接表单 submit 监听不触发；普通测试按钮仍能调用 RPC。新增 forms.js 统一绑定普通按钮 click、兼容程序派发的 submit（始终 preventDefault）及输入框纯 Enter。忽略 IME、长按、修饰键、textarea、select、复选框和按钮，保留这些控件原生行为。三个确认按钮均使用 type=button。连接操作在进入 pending 并禁用控件之前运行 reportValidity，防止 disabled 控件被原生约束校验跳过。

浏览器回归使用 Playwright 的真实 Chromium、源码内联的实际 UI 与仅 allow-scripts 的 srcdoc iframe。RPC 替身返回合成连接、对象和状态；不载入本地 file URL、不连接数据库。旧 0.9.1 包解出的原始 UI 用同一脚本复现测试成功而连接点击无 RPC；修复版本覆盖完整点击流程和键盘确认。
