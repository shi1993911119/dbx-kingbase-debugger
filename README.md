# DBX 金仓 PL/SQL 调试器 0.9.2

本地开发插件，目标为 DBX `v0.6.65-beta.20261103.1`、Windows 10／11 x64／macOS arm64 和 KingbaseES `V008R006C007B0024` Oracle 兼容模式。0.9.0 新增 Windows x64 启动器与 Windows 凭据管理器支持，0.9.1 加入 DataGrip 默认快捷键，0.9.2 修复 Windows 插件沙箱内“保存并连接”无响应的问题，参数确认和粘贴解析同时改为直接响应按钮点击。

包文件：`dist/local.kingbase.debugger-0.9.2-windows-x64.dbxp` 与 `dist/local.kingbase.debugger-0.9.2-darwin-arm64.dbxp`。Windows 安装说明见 `docs/WINDOWS.md`，历史包保留于 `dist/`。这是未签名开发包，尚未通过 DBX 商店审核。调试核心已在本机 DBX 内安装并完成独立测试过程的实库联调：两条专用连接、入口暂停、单步、行断点、变量、调用栈对象与行号、继续完成、输出以及停止。各版本验证记录与尚未覆盖的范围见 `docs/VALIDATION.md`。

## 已实现

- 顶部「金仓调试」快捷入口，插件内管理连接：新建、编辑、测试、保存、连接、断开与删除。重复点击入口复用同一工作台，保留参数、断点与运行状态；调试中禁止切换。连接不注册到 DBX 左侧列表。
- 可选“记住密码”：保存到 Windows 凭据管理器或 macOS 钥匙串，重开工作台后密码留空即可连接。界面只显示保存状态，支持更换和删除密码。

- 按模式与名称搜索 PL/SQL 过程和函数；部分名称包含匹配，忽略大小写，在数据库目录检索。以 OID 区分重载，单个结果自动选中。
- 参数独立窗口：每个参数一行，显示名称、方向（IN／OUT／INOUT）、真实类型、初始值和 NULL 选择；无需编写 JSON 或 SQL 引号。草稿仅在当前工作台内存中按连接与对象 OID 保存。
- 粘贴 DECLARE／BEGIN 调用块或 CALL 文本，自动按真实数据库签名填入参数；支持变量赋值和命名参数，重载需明确选择。导入本身不执行过程。
- JDBC 参数绑定；纯 IN 调用保持目标端类型转换，含 OUT／INOUT 时使用 CallableStatement 按真实 JDBC 类型绑定和注册输出。返回值以文本传到界面，保留大整数和小数精度。
- 建立两条固定物理连接：执行连接调用目标，控制连接创建监听器并执行调试 API。
- 入口暂停、单步进入、单步跳过、继续、停止。
- 暂停时点击源码行号添加或删除断点。
- 原始源码、变量、参数、调用栈与过程完成后的输出；完成后在右侧保留 OUT／INOUT 返回值，函数还会显示 RETURN。
- 配置栏的标签、输入框和按钮对齐；源码／右侧面板、变量／调用栈、工作区／输出均可拖动调整。变量与参数名称完整保留，长名称可在面板内横向滚动，参数窗口中完整换行。
- OUT 游标及 refcursor 域类型：读取全部返回游标后在底部表格显示，可切换多个结果；空结果保留列、NULL 游标显示 NULL。函数 RETURN 游标也可显示为结果集。
- 目标完成时清理仍在阻塞的控制请求；停止、异常、超时及连接关闭清理两条连接。
- 会话 generation 和事件 revision 校验，丢弃过期请求和事件。

本插件通过官方 JDBC 建立两条专用连接。连接配置保存在宿主提供的插件数据目录 `DBX_PLUGIN_DATA_DIR/debugger-connections.json`，升级后保留；仅持久化名称、主机、端口、库名、用户名、JDBC 路径和超时。密码在插件窗口本地输入；勾选“记住密码”时另存 Windows 凭据管理器或本机 macOS 登录钥匙串，不写入 JSON、浏览器存储、命令行或日志；Windows 凭据仅在本机当前用户下持久化，macOS 项不同步到 iCloud。未勾选时只供本次连接使用，断开或关闭后清除内存。现有 DBX 普通 Kingbase 连接仍可正常使用，其已保存凭据不由本插件读取。

## 本机安装与首次调试

1. 在 DBX 插件中心 → 设置中允许手动安装未签名开发包，再选择上述 `.dbxp`。原生后端按当前 OS 用户权限运行，仅安装你已审阅和信任的本地构建。
2. 点击顶部 **金仓调试**，在插件的 **连接管理…** 窗口选择“新建”。以下均为虚构示例，请按自己的环境填写：

   | 字段 | 示例值 |
   | --- | --- |
   | 连接名称 | 示例调试连接 |
   | 主机 | localhost |
   | 端口 | 54321 |
   | 数据库 | demo_db（请填写实际库名） |
   | 用户名 | demo_user |
   | 密码 | 在 DBX 本地输入，不放入脚本或聊天 |
   | Kingbase JDBC 文件绝对路径 | /path/to/kingbase8.jar |
   | 连接超时 | 30 秒 |

3. 测试连接。预检查会打开两条 JDBC 连接，核对实际数据库、不同 PID 和调试 API，然后关闭测试连接。
4. 要免去重复输入，请勾选“记住密码（macOS 钥匙串）”，然后点击“保存并连接”。连接成功后才更新已记住的密码。以后从顶部「金仓调试」进入，选择已保存的连接，密码留空即可连接。插件中心的“打开”也可进入同一工作台。模式默认取当前连接用户名，也可改为实际目标模式；输入 `dbx_debug_probe` 搜索，唯一结果会自动选中。点击“填写参数…”打开窗口，在 `p_seed`（integer）一行输入 `7` 并保存。
5. 点击“开始调试”，在参数窗口确认 `p_seed = 7` 后再次点击“开始调试”。确认入口暂停；单步、查看变量，再用“停止”结束第一次验证。

插件使用本机 Java 11+，启动器会寻找已安装 JDK 和 DBeaver 的 JRE。可通过 `DBX_KINGBASE_JAVA` 指定 java 可执行文件绝对路径。Kingbase 专有 JDBC 文件不随包分发，连接表单指定本机官方驱动路径。

## 顶部入口位置

在 **插件中心 → 设置 → 全局配置** 开启「显示插件快捷入口」，将「显示位置」设为 **更新按钮左侧（浮动）**。顶部图标的悬停提示为「金仓调试」。该设置由 DBX 统一管理，会同时改变其他插件快捷入口的位置。连接管理全部位于插件内，不向左侧添加连接。

入口通过 DBX 官方 command／appToolbar 扩展实现，无需修改宿主。插件不读取宿主普通连接列表或凭据，私有连接 ID 只用于本插件后端，不作为宿主 connectionId。顶部入口不执行任何过程。升级后，原 0.6.0 的左侧插件连接需要在完成新连接验证后手动删除；删除连接配置不会删除数据库对象。

## 调试快捷键

参照 JetBrains DataGrip 的默认 Windows／macOS 键位，插件根据运行平台显示按钮提示和无障碍快捷键标记。

| 操作 | Windows | macOS |
| --- | --- | --- |
| 单步跳过 | F8 | F8 |
| 单步进入 | F7 | F7 |
| 继续 | F9 | ⌘⌥R（Command+Option+R） |
| 停止 | Ctrl+F2 | ⌘F2（Command+F2） |
| 开始调试 | Shift+F9 | ⌃D（Control+D） |
| 切换行断点 | Ctrl+F8 | ⌘F8（Command+F8） |

先点击调试工作台使其获得焦点。单步、继续和断点仅在暂停状态可用；停止在调试活动期间可用，也可取消尚在等待的单步请求。开始快捷键先打开参数确认窗口，不会绕过确认直接执行。

切换断点优先使用源码中当前聚焦／选中的行，其次使用最后点击的源码行，尚未选行时使用当前执行行。源码可按 Tab 聚焦；聚焦行号后也可使用快捷键切换断点。输入框、下拉框、可编辑内容和参数／连接／粘贴文本窗口中不触发调试快捷键；长按不重复提交，同一时刻只发送一个单步请求。工作台外或未激活的标签页不注册全局快捷键。部分键盘需要配合 Fn 才发送 F7／F8。

键位来源：JetBrains 官方 `reference-keymap-win-default.html`、`reference-keymap-mac-default.html`（DataGrip Help）。当前映射对应插件已有的调试能力。

## 调整工作区

- 拖动源码与右侧面板之间的竖分隔条，向左拖可扩大变量和调用栈的宽度。
- 拖动变量与调用栈之间的横分隔条，分别调整两块区域的高度。底部输出区上方的横分隔条可调整输出高度。
- 双击分隔条恢复该处的默认比例；选中分隔条后可用方向键微调，Shift 加方向键加大步幅，Enter 恢复默认比例。
- 变量、参数与调用栈对象名称不显示省略号；过长时在所在面板内横向滚动，悬停单元格也能查看完整文本。参数窗口中的长名称会完整换行。

比例仅保存在当前工作台内存中，关闭后恢复默认。更新插件会关闭工作台，连接配置和已记住的密码保留。未记住的密码需要重新输入。

## 记住密码

- 初次在本地输入密码，勾选“记住密码（macOS 钥匙串）”。点“保存并连接”会先验证连接，成功后记住；连接失败保留原来已保存的密码。“测试”只验证连接，不存储密码。
- “保存配置”也可明确保存密码，无需先连接；勾选时输入内容会替换已保存密码，留空且已有密码时保留原值。没有已保存项时，留空代表显式保存空密码。
- 下次打开显示“已保存，留空使用；输入可更换”，密码框保持空白。点击“保存并连接”时后端从钥匙串读取，不把密码返回界面。
- 更换密码：先断开，输入新密码并保持勾选，再保存或连接。删除密码：取消勾选并点“保存配置”。删除连接配置也会删除对应的钥匙串项。正常断开、关闭工作台、重启和升级不会删除已记住的密码。
- 密码按连接 ID 与主机、端口、库名、用户名绑定；改这些字段时不会沿用旧密码，需为新目的地输入密码。仅改连接名称或 JDBC 路径不会删除密码。
- 若 macOS 弹出钥匙串授权窗口，请在本机完成授权。访问失败会提示重试或手动输入；钥匙串组件不可用时“记住密码”禁用，不回退为明文保存。

## 参数窗口说明

- 每行依次显示序号、名称、方向、类型、初始值和 NULL 选择。无名称的参数显示 `$1`、`$2` 等位置名。
- 字符串直接填写原文，不加 SQL 单引号。空白、单引号、日期、大整数等以原始文本交给数据库类型转换。
- 所有参数首次打开默认勾选 NULL。IN／INOUT 输入框可以直接输入，输入任意非空文本会自动解除 NULL；清空输入后恢复 NULL，手动勾选 NULL 会清空原值。需要空字符串时可手动取消 NULL 并留空。Oracle 兼容模式可能由服务器进一步将空字符串归为空值。
- “保存参数”只保存当前窗口中的参数，不执行对象；“取消”、关闭按钮或 Escape 丢弃本次未保存的修改。
- 点击工作台“开始调试”会先打开参数确认窗口，确认后才执行。无参数对象也显示确认窗口。
- 切换对象不会串用其他对象的参数；重开工作台会清空草稿。参数默认值不自动求值，每个 IN 参数均显式绑定。
- IN 正常填写输入值；OUT 固定为 NULL，输入框和复选框禁用；INOUT 可填写初始值或勾选 NULL。OUT 由驱动注册为输出，不会误绑定成 INOUT。
- 完成后右侧按声明顺序显示输出参数的名称、方向、类型和值。含输出参数的标量函数另显示 RETURN；返回的 INOUT 值不会覆盖已保存的初值。
- 后端按全部参数声明顺序接收数组，纯 OUT 的位置必须为 null；界面自动生成，无需手写。

## 粘贴调用文本

点击顶部“粘贴调用文本…”，粘贴整段 `DECLARE … BEGIN … END;`，再点“解析并填入参数”。插件识别声明、`:=`／`DEFAULT` 初值、调用前的简单赋值、一次过程／函数调用，以及调用后的 `DBMS_OUTPUT.PUT_LINE`。函数也可使用 `result := schema.function_name(...)`。支持普通／N／q 引用字符串、转义单引号、注释、数字、布尔、NULL、未赋值变量、位置及 `name => value` 命名参数。数字保留原文本精度；空字符串 `''`（包括 N／q 引用的空字符串）统一按 NULL 导入并勾选 NULL；未赋值变量同样为 NULL。有内容的字符串、数字 0 和布尔值保留原值。

模式使用调用中的限定名，未写模式则使用工作台当前模式。过程名按完整名称匹配；多个重载均匹配时必须选择签名和 OID。数据库元数据决定最终名称、类型和方向，不依赖调用块的局部变量名：例如局部 `list` 可映射到数据库 OUT 参数 `output_cursor`，OUT 初值一律 NULL，含游标时继续使用既有 JDBC 输出注册。

导入成功后显示逐行参数窗口，可检查、修改、保存。随后点击工作台“开始调试”，确认后才执行。调用块末尾的打印语句仅识别并计数，不随块原样执行；完成后的 OUT／INOUT 返回值在右侧显示，游标在底部显示，过程自身输出沿原路径收集。

本功能导入调用数据，不将匿名块本身设为调试目标。不支持表达式求值、SELECT／DML、控制流、异常块、多次目标调用、调用后继续赋值、包内过程入口或省略参数；遇到这些语法会提示修改，不会把未知表达式猜成 NULL。每次最多 256 Ki 字符，草稿和粘贴文本仅在工作台内存保存，切换连接后清空。

## 游标结果集

`output_cursor OUT "demo_user"."demo_cursor.t_cursor"` 在参数窗口固定为 NULL，直接开始调试即可。暂停时仍可单步和查看变量；目标正常结束后，底部自动切到“结果集”，下拉选择返回游标。右侧保留各 OUT／INOUT 参数和值；NULL 游标不生成表格，空游标会保留表头并显示 0 行。重复列名和大小写按原顺序保留，大整数、十进制数以文本显示。

每个游标最多展示 2000 行、256 列；一次调用的全部输出共用约 2Mi 字符上限。达到行数或大小上限会明确显示“已截断”。这不是服务器分页：当前 JDBC 对 refcursor 的 `getObject` 可能先把游标整体读入驱动内存，插件限制的是保留和展示的结果大小。大结果建议在过程查询中自行限制范围。结果仅保存在当前调试会话内存，下一轮或关闭连接后清除。

## 当前范围和限制

- 支持独立过程和函数的 IN／OUT／INOUT 标量，以及 OUT 游标。含输出参数的调用支持整数、numeric／number、实数、布尔、普通字符文本、日期和时间等内置标量类型；OUT refcursor 和底层为 refcursor 的域类型按数据库目录识别，包括 `"demo_user"."demo_cursor.t_cursor"`。游标参数仅开放 OUT。LOB、数组、复合／record、其他自定义类型、多态、TABLE、VARIADIC 尚未实现，会在执行前提示。包内游标类型可用；包成员作为调试入口、触发器和匿名块入口尚未完成。
- 从入口暂停后设置后续行断点。首版不持久化断点，不支持修改变量或选择任意调用帧。
- 单步进入子过程时可以显示该子过程源码和当前帧变量，但不提供源代码编辑或编译按钮。
- 调试会实际执行目标过程。含游标的调用在同一条执行连接内开启事务，读取并关闭返回游标后提交；读取或执行异常时回滚，停止时取消请求并中止专用连接。无游标调用沿用自动提交。过程自己已经提交的内容不能靠“停止”撤销。测试只使用不访问业务表的独立过程。
- 过程输出通过 JDBC warning 在执行返回后收集，首版不保证实时输出。每次调试最长 10 分钟；目标等待连接超时为 15 秒，暂停等待命令超时为 300 秒。
- 每次搜索返回最多 500 个对象；超过时提示输入更完整的名称，搜索会在整个模式的数据库目录中重新匹配。检查结果最多 2000 行和约 2Mi 字符。错误消息返回 SQLSTATE，避免把驱动异常中的凭据或连接串回传到 UI。
- 工作台同时使用一个插件内连接，并调试一个目标。切换成功才关闭原空闲连接，失败保留原连接。关闭工作台会关闭两条专用连接；在途建立请求可被关闭通知取消。
- 插件内连接直连填写的主机和端口，不复用 DBX 普通连接的 SSH／代理隧道。没有新增 TLS 配置表单。

本仓库文档和测试夹具只使用虚构连接与业务数据。实际连接配置、凭据、IDE 数据源和数据库导出文件应保留在本机，不要加入 Git。

## 开发与测试

需要 Java JDK 11+、Go 1.24+、Node.js、官方 `@dbx-app/plugin-cli@0.1.9`。Go 构建原生启动器；调试核心用 Java JDBC；macOS 构建另需 Swift，Security helper 访问本插件自己的钥匙串项；Windows helper 使用 Go 调用 CredReadW／CredWriteW／CredDeleteW。

```sh
sh scripts/test-backend.sh
npm install
npm run test:ui
npm run test:import
npm run test:launcher
npm run test:layout
npm run test:shortcuts
sh scripts/build.sh
python3 scripts/test-keychain.py
sh scripts/test-keychain-backend.sh
```

`scripts/build.sh` 先编译 Java，再调用官方 `dbx-plugin package`。`dbx-plugin.toml` 中的 Go 后端是 JVM 启动器，不包含数据库驱动代码。macOS launcher 使用 `syscall.Exec` 保持同一进程 PID 和标准输入输出。Windows launcher 继承标准输入输出，并用私有 Windows Job Object 在自身退出／被强制终止时清理 Java 与后代进程。Windows 原生构建使用 `scripts/build-windows.ps1`，需在 Windows 上运行 x64 版官方 CLI；脚本使用临时 staging，只打包该平台的 helper，不混入 Mac 二进制。

后台自动化使用可阻塞的 JDBC 测试替身，覆盖并发、清理、类型引用和参数绑定；这些测试不连接数据库。详见 `docs/VALIDATION.md`，其中明确区分实库结果、模拟测试和宿主待验证项。

主要来源：DBX 官方仓库 commit `5b004b973dd2be2d8b327cb50864cd648445056b` 的 `plugins/README.md`、`plugins/manifest.schema.json` 和 Go SDK；金仓版本配套 `plsql_pldbgapi` 手册。源码出处与实测差异记录在 `docs/VALIDATION.md`。

## 浏览器表单回归测试

安装开发依赖后运行 `npx playwright install chromium`、`npm run test:browser`。也可通过 `DBX_TEST_CHROMIUM` 指定已有 Chromium／Chrome 的可执行文件绝对路径。测试在仅有 `allow-scripts` 权限的 iframe 中使用实际 UI、真实点击和键盘事件；RPC 使用合成数据，不连接数据库。测试覆盖保存密码连接、参数保存和执行确认、粘贴解析、输入框回车、F8、无效配置及失败重试。对旧包的回归复现可设置 `DBX_TEST_UI_ROOT` 指向解包目录并设置 `DBX_EXPECT_BLOCKED_SUBMIT=1`。
